# Comfy Portal design system

## Source and precedence

The approved business flows are on Figma page 08 (Dark), in the Comfy Portal file linked below. Page 09 (Light) is paused. Follow the latest reviewed Figma screens and component contracts; the earlier Downloads HTML and page 07 flows are historical references, not the current navigation specification. Preserve the existing Run node controls and their behavior.

## Architecture

Keep Gluestack UI core 5, the existing `components/ui` creators, NativeWind 4, theme provider, Expo Router and native platform integrations. Branded compositions live in `components/ui/design-system` and consume the existing Gluestack components. Do not introduce a DOM/WebView-based component kit or a second interaction framework. `constants/design-tokens.ts` is the review source for the new visual values. The review library lives in Figma: https://www.figma.com/design/yoM0p3Momt2fioUJ2QkEc1/comfy-portal. Page and component IDs are indexed in design/figma-library.json; reference node contracts live in design/node-specs.json. The app contains production UI only.

## Foundations

- Colour: neutral paper/card/well surfaces; tint is removed. Selection, primary actions and focus use ink. `constants/design-tokens.ts` owns every colour and [surface-system.md](surface-system.md) is the reference. Semantic online/warning/error colours are kept.
- Type: Barlow for all Latin UI text, titles and numbers (Regular/Medium/SemiBold/Bold, true italics), registered once in `constants/font-assets.ts`. Scale: title 26/30, section 14/20, body 13/20, label 12/18, metadata 11/16. Respect font scaling. `node scripts/audit-typography.cjs` regenerates `typography-inventory.json`; CI-style check with `--check`.
- Shape: every corner alias reads the single value in `cornerRadius` in `constants/design-tokens.ts` (currently 4pt); circles stay circular; flush sheet edges are square.
- Restrained, precise, relaxed: paper, content cards and recessed controls, ink emphasis, fine structural boundaries. No gradients, decorative shadows or press scaling.
- All existing Gluestack text slots use the shared RN font adapter; `Text`, `Heading`, `Copy`, native inputs and web text resolve the same faces. Input fonts belong to AdaptiveTextInput / SheetAwareTextInput. Keep native system dialogs/keyboards and externally hosted documentation under their own platform/site typography.
- Spacing is relationship-based, using `designTokens.layout` and Figma `CP / Metrics → layout/*`. Label-to-value is 4, related content and separate list items are 8, form-field groups are 12, container insets are 16, screen section gaps are 24, and horizontal screen gutters are 20. A flat sequence of labels, controls and headings with one repeated gap is forbidden: group relationships first, then space the groups.
- Joined lists use zero item gap, one shared 10-point-radius outline, and 1-point dividers. Row insets are 12 horizontal and 10 vertical. Do not add per-row cards or radii inside the list. Standalone lists use an 8-point gap; do not mix both treatments within a list.
- Compact badge insets (6 horizontal, 2 vertical), 4-point icon-label gap, and 6-point status-dot gap are named exceptions, not arbitrary spacing choices. Touch targets remain at least 44 points; hit-area space must not be added a second time as decorative padding.
- Sheet appearance comes from `useSheetAppearance` in the reviewed overlays composition. Modal Sheet, ThemedBottomSheetModal and the Run PersistentSheet share paper fill, 20-point top corners, a paper grabber zone 24 points high and a muted 32×3 indicator. The persistent panel retains a fine line-color outline to separate it from the undimmed workspace; modal surfaces retain their backdrop. Feature pages configure content and behavior, not another set of background/handle styles.
- Sheets have 16-point content insets. The grabber zone and measured bottom safe-area inset are platform geometry, separate from content spacing. Never add an empty text node or spacer to represent the safe area.
- Avoid double spacing: an unfilled section wrapper has zero padding; an actual panel owns its 16-point inset. Light and Dark use identical geometry and spacing bindings. Align icons vertically to the center of short two-line rows.
- Compact visual controls 28/36/44. Design buttons default to a 36-point visible surface (28 for small actions), 8-point radius, 13-point text and 14-point icons; their enclosing touch target remains 44 points. Icon+label buttons use a 16-point icon slot, 4-point label gap and 10-point horizontal padding (8 for small). Icon-only buttons have zero content padding, a centered 36×36 surface (28×28 small), and a 44×44 touch target. Stepper cells may stretch their touch target to preserve the 1:2:1 layout. On touch screens provide 44-point interaction space; do not overlap expanded hit areas. Inputs use 44-point minimum height for editing while preserving compact typography.
- Lucide only, 24-unit source geometry with viewBox-compensated strokes through iconStroke(size), sizes 14/16/18/20/24. Icon-only buttons require accessible names.
- One filled primary action per business view. Secondary actions have a fine border, tertiary actions are text. Filled and outlined buttons reserve the same 1-point inside border within the same visible surface bounds; filled buttons paint that border with their fill color so their painted outer edge matches the outline variant. Disabled opacity .4. Destructive actions use explicit wording and confirmation.
- Status includes words plus shape: green solid reachable (dark #4ade80, light #15803d), hollow offline, slow pulse busy. Never communicate state using color or animation alone.
- Button first paint and selection: labels must be visible on mount. Commit label color, fill and inside border together; do not animate background/border colors independently or inherit link underlines from the underlying button variant. Press opacity and dedicated tab indicators retain their subtle transitions.
- Bottom tab indicator: 16×2 points at rest, 0.75-point corner radius. The leading edge travels first (190ms ease-out); the trailing edge follows after 45ms and restores the short line. New selections cancel pending motion and continue from the current bounds. First layout, resizing and reduced motion position the indicator immediately.
- Motion: 160ms selections, 200ms state change, 240ms progress, 1000ms ring loader. General loading indicators and button spinners use the shared ring, with a 180ms appearance/collapse transition; no native petal ActivityIndicator. Refresh icon actions retain the same icon and geometry, rotate clockwise with a 1000ms linear cycle while pending, then finish forwards at rest within 200ms; no icon replacement, scale or collapse. Reduced motion keeps the refresh icon static with an accessible busy/disabled state. Respect reduced motion, stop loops off-screen; no springs or bouncing.

## Component contracts

- Sheet dismissal: bottom sheets do not show standalone header Close or dismissal-only Done buttons. Use backdrop and drag dismissal; preserve actions that save/apply data or perform a task. Explicitly nondismissible flows retain their existing restrictions.
- Hardware selection: keep the AppBar, environment name, provider filters and GPU search outside the scrolling results. Pin Next above the bottom safe area; disable it until an eligible offer is selected. Refresh inventory with pull-to-refresh, not a separate refresh icon.
- Forms: filled well, 1-point reserved border that becomes ink on focus; invalid state has an explanatory message. Search actually filters; steppers clamp and preserve decimals; sliders retain Gluestack gesture/accessibility behavior and include decrement/increment buttons using the same step and bounds.
- Selection: use Gluestack radio/checkbox/select primitives. Use the existing Gorhom bottom sheet for native long-list selection and editing. Preserve keyboard avoidance, back dismissal and safe area.
- Selector sheets share one header/list contract: 16-point horizontal insets and 16 points between the last header element (title or search) and the first option, with or without search/actions; title-to-search gap 12. Lists have an 8-point row gap. Option names use 13/20 Barlow and ink in both states, names Medium in both states, descriptions 12/18 muted. Text/model rows are unfilled at rest; selection uses tintSurface, a reserved 1-point tint outline and tint Check. Media tiles use card, 12-point corners and the same selection treatment; selecting must not alter border width or thumbnail geometry. Two-column grids share exact equal widths, including an odd final item. Labels may wrap to two lines before truncation. Search uses one controlled query, updates immediately and resets on reopening; no stale local value or delayed callback after dismissal.
- Selector sheets use stackBehavior="push" so selection inside an existing form sheet preserves the parent form and returns to it on selection or dismissal. Do not minimize/unmount the parent selector trigger through the default switch behavior.
- Top-level collection creation: Servers and Environments use one unfilled Plus action in the top-right AppBar, with a 44-point target and matching icon size. Keep the entry in the same place for empty and populated lists; collection counts sit beside the main title; do not repeat a Your servers section heading or another add button. Tapping opens the corresponding creation sheet.
- Environment details pin Create instance below the scrolling recipe content on the paper surface, with the bottom safe-area inset and the same footer geometry as hardware selection.
- Server lifecycle: use the same ServerRow for connected servers, template builds and failures. Keep title, origin badge, address, status line in the same positions; management actions live on the card: a trailing ⋯ action (44pt target, flush with the content edge) and a long press both open one actions sheet (Edit connection, Copy address, Remove connection, and Destroy instance for rentals). Progress is reported from supervisor steps/model counts, never an invented overall percentage. Incomplete/failed builds open installation details; registered servers open saved workflows. Removal is reached only from the card's actions sheet and requires confirmation; the server destination's settings sheet edits the connection but does not remove it.
- Server origin badges use a quiet raised surface, fine outline, small corners and the shared 6/2-point badge insets. Manual and Template build keep the same treatment; tapping the badge opens the card.
- Server cards show all device models reported by ComfyUI core /system_stats in the bottom-right metadata slot, with a GPU icon and a single truncated text line capped to half the footer width. Hide the model catalogue count. Keep connection status on the left; rentals also retain their cost there when hardware is present. Group repeated models with their count (2 × RTX 4090); separate different models with a middle dot. Keep the complete summary in the accessible description. Persist the complete list independently of reachability; offline, missing/malformed hardware data and failed requests retain the last successful list. Connection checks and detail-page metrics requests update it on a valid observation. Existing single-device caches remain readable. Only report devices exposed by the endpoint, never infer other installed GPUs.
- Lists: grouped compact rows, subtle separators, flexible text column, fixed trailing metadata. Show online/offline and image-present/image-empty variants. Workflow thumbnails reserve a non-shrinking 44-point square in both states.
- Nodes: retain ComfyUI class and parameter names. Boolean/enable-disable node parameters use labeled segmented choices. Steppers allocate button/value/button widths in a 1:2:1 ratio with 44-point minimum touch targets. All reference node types share the same controls; immutable and unknown types need explicit states. Figma examples are fixtures, not live requests.
- Model selection: names are primary; previews are optional. Node triggers keep a 48-point row and omit the thumbnail slot when no preview exists. Searchable sheet rows align names using equal-width thumbnail/icon slots; tapping a thumbnail opens a larger preview within the sheet. Missing/failed images fall back gracefully. LoRA strengths remain in the node.
- Run AppBar shows the workflow title and results action. Omit the server name and idle Ready row with no reserved empty space; active generation/saving progress remains visible.
- Generation: show completed/total nodes separately from current-node value/max steps and output-file download progress. Cached nodes count as completed; node counts are not elapsed-time estimates. Nodes without progress events use an indeterminate ring. Reset the step bar on node changes. Preserve queueing, cancellation, saving and failure variants in the Figma library. Primary button backgrounds transition in 180ms and label changes in 160ms, without scaling or bounce.
- Feedback: flat dialogs, specific errors, restrained progress/skeleton, reversible demo actions. No pretend pull-to-refresh on static specimens.
- Navigation: Expo Router routes, existing responsive sidebar, a fixed bottom bar with a centered 16x2 indicator below the label of the active tab. Tab math must use measured width and the actual item count.

## Business information architecture

- The four primary destinations are Servers, Gallery, Environments and Settings. A Library or Runs tab is not part of the product.
- Servers is the entry point. Manual connections may be anywhere; do not infer that they are on a local network. User-managed servers and app-created instances share the same standalone card-surface rows, with 8-point spacing, 12/10-point insets and quiet origin badges. Add opens the existing connection form.
- Servers search uses the same Field and title/search/list spacing as Environments. Match visible server/build names and addresses without changing the total collection count. Search stays inside the refresh surface, which fills the viewport even for empty results; pulling refreshes all connections, preserves the query and dismisses the keyboard. Environments uses native scrolling and vertical overscroll even with empty or short content, without a refresh action.
- A ready server opens its Workflows / Gallery destination. Its name belongs in the AppBar. Connection settings use a bottom sheet. A pending installation opens Setup in a sheet; a newly created installation uses the full Setup view.
- Workflow content is a reusable on-device asset. A server binding makes a copy runnable on a particular connection. Imports create independent copies and resolve duplicate display names without overwriting another workflow. The internal reusable asset catalog remains available to import sheets without a Library tab.
- Gallery owns generated outputs independently of connections. Use All / Images / Videos filters and an ungrouped grid. Images and videos use the existing native media preview. Empty states use the approved local illustration.
- Server and environment cards share one borderless content surface with 16-point padding, no decorative leading icon tile, no internal divider, and 12 points between identity and summary. Titles and summaries align to one leading edge; the origin badge sits at the upper right. They share title/subtitle geometry: section 14/20, metadata 11/16 and a 4-point gap; only machine addresses use the mono face. Names and machine addresses truncate with a trailing ellipsis on one line; environment descriptions truncate after two lines and full text remains in the card accessibility description. Empty or whitespace-only descriptions show the muted placeholder No description yet. Environment footers stay on one line with model, extension and workflow icons, counts and text labels, distributed with space-between across the full row (first left, last right, equal gaps). Omit total model size, keep the metadata font size and truncate oversized text rather than wrap or shrink the type. The full count labels remain in the accessible card hint. Environment list cards open the recipe details across their entire surface. Create instance belongs on the details page; the list has no rental shortcut. Both creation and editing sheets use the same multiline Description Field.
- Environments contain installation recipes: models, extension repository URLs, workflow snapshots and optional Ollama models. They contain no provider, GPU selection, disk allocation or hourly rental rate.
- Create instance selects hardware, reviews the actual quote and account balance, then starts installation from immutable environment and hardware snapshots. Editing or removing the source environment must not change the installation.
- Setup groups base preparation, extensions, models, workflows and startup checks. Every item has its own real progress/state. Unknown sizes and unavailable metrics remain explicitly unknown.
- Settings keeps the existing product items; it is not a second server-management hierarchy.

## Data ownership and persistence

- WorkflowAsset owns the graph, name and thumbnail. WorkflowBinding owns its server association, source metadata and usage time. The legacy-shaped WorkflowRecord is a derived read model for the existing node editor, never a second persisted source of truth.
- Removing a connection removes bindings, not reusable assets or generated media. Removing a workflow binding also preserves its reusable content. Thumbnail files live in workflow-thumbnails-v2, outside connection cleanup directories.
- Environment records and exported environment files are validated with the existing Zod dependency. Exports omit local IDs and all hardware details. Unsupported export versions fail explicitly; malformed resources must not be silently discarded.
- HardwareSelection records the provider, provider offer ID, GPU details, disk and quote time. Its price scope distinguishes a complete instance quote from a GPU-only starting rate. A launch captures a deep snapshot before any asynchronous external request.
- A pending generation is identified by (serverId, promptId), and owns its submitted graph snapshot. Never identify a task by promptId alone or read its graph from the currently edited workflow.
- Output identity is (serverId, promptId, filename, subfolder, output type). A temporary download path is not an identity. Persist each completed output before downloading the next; recovery skips committed output identities.
- Media browsing uses Server → Workflow → Results for a particular runnable binding, and the top-level Gallery for the entire collection. Source server and workflow IDs are filter keys, never media ownership; the source-name snapshots and workflowAssetId support readable provenance and grouping after the original binding is removed. Both views read the same media records, with no duplicate files or cascading deletion.
- Native media bytes live in media-v2. The media index includes source identity and the generating graph snapshot. Web currently persists source references rather than an offline byte cache; do not describe it as offline media storage.
- Pending requests are flushed to durable storage before submission. Media index writes are serialized and flushed before retiring a pending job. A failed storage commit must leave recovery possible.
- Reachability, loading flags and request locks are runtime observations. They must not become authoritative saved connection state after a restart.
- Credentials stay in the existing platform secure-storage abstraction, separate from environment files. Existing rental records must remain reachable for billing management even while editable business-data schemas are replaced.

- Cloud rentals use a provider-qualified identity (vast:123 or runpod:opaque-id). Provider adapters normalize distinct status and port responses; no RunPod instance is represented as a fake Vast numeric ID.
- A durable LaunchRequest precedes the billable provider call. It records a random provider-visible label, immutable recipe/hardware snapshots, a credential hash and any returned receipt. It contains no provider API key. An ambiguous response is reconciled by that label before another order with the same credential; it never silently repeats creation.
- Credential writes and rental records have explicit commit boundaries. The UI confirms saving only after secure storage succeeds. SSH registration is scoped to the provider credential rather than a global Boolean.
- Runtime images deploy separately from app code. The current default remains the published sha-bebbb7b image. Version 2 source adds direct SSH for RunPod and per-extension failure reporting. RunPod creation stays disabled until a tested immutable image is set through EXPO_PUBLIC_CP_RUNTIME_IMAGE, EXPO_PUBLIC_CP_RUNTIME_OLLAMA_IMAGE (when needed), and EXPO_PUBLIC_CP_RUNTIME_VERSION=2. Source changes alone do not update existing rentals.

- AppBar uses the same 20-point content gutters as the screen below. The back icon occupies a 20-point layout slot at the leading gutter, with its 44-point hit area extended outward; the title follows after 12 points. Trailing icon-only actions use a 20-point icon aligned to the trailing content edge, with their 44-point hit area extending inward. Plain trailing text ends on that same edge. The touch box must not become an extra visual inset. Secondary-page AppBar titles default to 20/24.

- Server details show workflows directly, with a compact Workflows heading, count and Import action; do not show server-level Gallery or resource tabs. The top content card contains a truncated GPU summary, a row with truncated host and latency, then current used/total VRAM with the existing 2-point Meter (explicitly GPU 1 for multi-device servers). Render the meter only for observed used/total values with a positive capacity; unknown usage is not zero. The card has 12/10-point insets and 8-point row gaps, and opens Hardware details across its entire surface. Keep connection status and all disk information in that sheet, with complete GPU names and used/total/free readings. Loading, unavailable and last-known GPU states remain distinct; do not present cached VRAM or disk readings as current. Reserve the main viewport for the workflow list.

Settings footer: one centered, muted system-sans line at 10/16 with 12-point top spacing. No emblem, rules, background or additional title.

FilterChips: shared single-choice filters for Gallery media, environment model types and hardware providers, in components/ui/design-system/filter-chips.tsx. Use 28-point visible surfaces, 6-point corners, 12/18 labels and optional 10/16 counts, inside independent 44-point touch targets. The page owns horizontal gutters outside FilterChips, so its clipping viewport aligns with the search box and result cards rather than the screen edge. Never substitute scroll-content padding for this viewport inset. The bounded horizontal scroll container clips children and never shrinks below its touch-target height when results grow. Show a passive paper-colored edge fade only on sides with more scrollable content; use a narrow 16-point eased gradient with a soft transparent tail, reduce its opacity over the final 16 points of scroll distance and transition changes over 160 ms (immediate with reduced motion). It reaches zero at the corresponding end or when everything fits. Edge fades are overflow cues, not decorative shadows. Keep external spacing on the page: 12 points from the filter/search region to the results in every state, including All and empty results. Unselected filters are transparent; selected filters use tintSurface with tint text; paint label and background together without mount animation. Expose radio selection semantics.

Workflow addition uses Toast for source-reading and saving outcomes rather than a trailing inline error. Reading valid JSON opens review and says Workflow loaded; only saving says Workflow added. Empty/invalid clipboard content, clipboard access failures and save failures show actionable error Toast while preserving retry. A saved workflow with a failed thumbnail produces one partial-success Toast, never an error immediately overwritten by success.

Toast positioning: render AppToast at the root and in native modal hosts. The host owns top safe-area inset + 8 and bottom inset + 8. showToast accepts content only; feature callers must not override offsets.

### Custom pull to refresh

- Use shared RefreshScrollView / RefreshFlatList for refreshable lists. Keep fixed headers and footers outside the refresh surface.
- Native Gesture Handler tracks top-of-list downward drags; Reanimated renders on the UI thread. A monochrome 8×8 pixel field (28 pt) gathers from a 24 pt horizontal / 18 pt vertical scatter as the user pulls, using a quadratic gathering curve so early movement remains visible; smooth diagonal waves resolve noise into a tiny landscape. Threshold: 60 pt after resistance; loading offset: 48 pt; noise cycle: 1800 ms; enter: 200 ms; minimum gesture refresh display: 650 ms; settle: 300 ms. Pull resistance increases continuously instead of hitting a hard cap.
- Refresh once per released gesture, await the real request and the minimum display duration concurrently, then return. Apply results immediately; the minimum duration affects feedback only. Prop updates must not restart the gesture animation. On completion, resolve the framed landscape over 220 ms, then hold the fully resolved image for at least 650 ms, and preserve it during the exit. This is activity feedback, not measured generation progress. Below-threshold gestures cancel. Stop animation on blur/unmount and respect reduced motion. No native spinner overlay.

- Current default: portrait. Return to latent dot-field resolution using a locally sampled public-domain Mona Lisa head crop. 18×24 circular dots, 1.3 pt pitch, 0.43 pt radius, four tonal levels and 16 grouped vector paths; monochrome with correct tonal polarity in both themes. Minimum activity 500 ms, resolve 600 ms, completed hold 500 ms. No network, external particles or convergence effect. Source and sampling geometry are recorded in assets/illustrations/mona-lisa-dots.ts.

- Portrait styling: prioritize clearly separated vector dots and a four-tone face silhouette over photographic sampling. Avoid dense halftone rendering that reads as a thumbnail.

- Shared artwork gallery: 12 locally bundled public-domain classics; render only four-tone circular SVG dots, never the reference JPEG. Preserve each painting’s aspect ratio within 32 pt (long edge 24 dots, 1.3 pt pitch). Select once when a downward pull activates; keep the selection stable through resolution and exit. A single app-wide shuffle bag exhausts all 12 before reuse and excludes immediate repeats across cycles and routes. No runtime downloads. Credits and vector data live in assets/illustrations/refresh-artworks.ts. All refreshable lists use the existing shared wrappers.

- Empty Gallery (Figma 2136:2226): preserve the approved vector geometry and static text. On an active native empty-state screen, gravity-driven parallax separates back card, front card and corner accents at depths -0.35/1/-0.55. Calibrate to the first valid holding angle; cap front-card movement at 7 pt horizontal, 3 pt vertical and 2.3 degrees. Use 32 ms sensor samples with 120 ms exponential smoothing; no spring, autonomous loop or shake action. Unmount sensors on blur/background, with media present, or reduced motion. Web and unavailable sensors keep the static illustration.

- Setup installation log opens a second Sheet with stackBehavior="push" at 75% height. Keep Setup mounted underneath, including installation polling and its scroll position. Dismiss the log via backdrop or drag to return to Setup; do not add a Done button. Log text is selectable and scrollable, uses monospace, and includes loading/error/refresh states; reopening fetches fresh data and ignores late responses after dismissal.

- Setup includes an outlined destructive Destroy instance action. Require confirmation naming the provider, instance ID, irreversible instance disk loss and separately billed storage. Call the provider destroy API, never just stop the supervisor. Keep the local record on provider failure; deduplicate requests and suppress installation advancement during destruction. Remove matching connection and provisioning state only after provider success.

- Destruction feedback: confirmation and Setup action show Destroying instance… with the shared ring and disabled repeat submission. Success requires an authenticated provider list confirming the exact instance is absent; a malformed response, rejected request or verification timeout is never success. Keep Setup mounted after record removal to display Check + Instance destroyed until acknowledged with Back to Servers. Failure remains visible in the confirmation with retry; do not dismiss automatically.

- Setup actions are a vertical related group: gap = designTokens.layout.related (8 pt). View installation log stays secondary; Destroy instance uses the filled destructive style, never an outline. Preserve shared action sizing and touch targets.

- Setup destruction overlays must use the same Gorhom Sheet stack as Setup (push), not a nested AlertDialog/RN modal. Lock drag/backdrop dismissal while destruction is pending. Retain errors in the child sheet. On success, wait for the child onDismiss callback before dismissing Setup; never unmount both layers in one event.

- Fixed sheet actions share the exact c.paper surface with the sheet background (light and dark), with no separate panel edge or shadow. Add/Edit Server use Gorhom measured footer margin adjustment plus only the safe-area inset and standard content inset; never add a second hardcoded footer-height spacer.

- Fixed footer motion: below the lowest open detent, cancel Gorhom’s viewport-anchoring compensation so the footer and sheet share exactly the same translation during presentation, downward dragging and dismissal. Derive the offset from the native animated sheet position and current detents; no second timer, delayed fade or independent enter/exit animation. At open detents preserve the standard keyboard-aware footer position.

- Setup offers one primary Destroy instance action. Only after destruction fails, offer Remove local record only or Cancel; local removal requires a separate confirmation. Confirm that it does not terminate resources or stop billing. Keep removal errors retryable and show a distinct local-removal success state; dismiss the parent only after the confirmation sheet dismisses.

- Portrait pull refresh: fast requests have a 100 ms minimum pending phase, 300 ms completion reveal, 160 ms readable hold and 300 ms return (about 860 ms total). Pending requests continuously reveal a portrait every 1100 ms, then choose the next artwork from the global non-repeating shuffle bag. Stop cycling on completion, blur or unmount; reduced motion skips animation and artificial holds.
